JETSON BOARDS
================================================================================

MONO16 (Y16 - 16-bit Greyscale)
────────────────────────────────

  640x480:
    v4l2-ctl -d /dev/video0 --stream-mmap \
      --set-fmt-video=width=640,height=480,pixelformat="Y16 " \
      --stream-count=1 --stream-to=video.raw

  1280x1024:
    v4l2-ctl -d /dev/video0 --stream-mmap \
      --set-fmt-video=width=1280,height=1024,pixelformat="Y16 " \
      --stream-count=1 --stream-to=video.raw


ARGB888 (32-bit AR24/BGRA or AB24/RGBA, depending on L4T version)
───────────────────────────────────────────────────────────────────

  The camera always transmits the same RGB888 bytes over CSI-2. What
  changes is which V4L2 fourcc reports this: AR24 (32-bit BGRA) on L4T
  32.x and all 35.x (including 35.4.1-35.6.4), and AB24 (32-bit RGBA) on
  L4T 36.x and later. NVIDIA's own vi5_formats.h/camera_common.c actually
  switched natively to RGBA32-only starting at 35.4.1, but EG re-adds
  AR24 alongside it through 35.6.4 (JetPack 5.x) because the
  gst-plugins-good 1.16.3 bundled there doesn't recognize the RGBA32
  V4L2 fourcc at all (v4l2-ctl itself is unaffected — this is purely a
  GStreamer limitation). Run eg_dt_camera_config_get.sh to see which one
  your board actually reports before picking an example below.

  640x480 (AR24 — L4T 32.x and all 35.x):
    v4l2-ctl -d /dev/video0 --stream-mmap \
      --set-fmt-video=width=640,height=480,pixelformat="AR24" \
      --stream-count=1 --stream-to=video.raw

  640x480 (AB24 — L4T 36.x and later):
    v4l2-ctl -d /dev/video0 --stream-mmap \
      --set-fmt-video=width=640,height=480,pixelformat="AB24" \
      --stream-count=1 --stream-to=video.raw

  1280x1024 (AR24 — L4T 32.x and all 35.x):
    v4l2-ctl -d /dev/video0 --stream-mmap \
      --set-fmt-video=width=1280,height=1024,pixelformat="AR24" \
      --stream-count=1 --stream-to=video.raw

  1280x1024 (AB24 — L4T 36.x and later):
    v4l2-ctl -d /dev/video0 --stream-mmap \
      --set-fmt-video=width=1280,height=1024,pixelformat="AB24" \
      --stream-count=1 --stream-to=video.raw

GSTREAMER EXAMPLES
───────────────────

Note on display sink:
  ximagesink is used in the examples below. It works on L4T 32.x and 35.x.
  On L4T 36.x and later, autovideosink is preferred (nveglglessink is no
  longer installed, so autovideosink cleanly selects waylandsink/ximagesink).
  On L4T 39.x (Ubuntu 24.04), ximagesink is broken by an XInput2 device-ID
  bug — use autovideosink there.
  Summary:
    - L4T 32.x / 35.x (Ubuntu 18.04 / 20.04): ximagesink
    - L4T 36.x         (Ubuntu 22.04):         autovideosink (or ximagesink)
    - L4T 39.x+        (Ubuntu 24.04+):        autovideosink


MONO16 (Y16 - 16-bit Greyscale)

  Capture to file (1 frame):
    gst-launch-1.0 v4l2src device="/dev/video0" num-buffers=1 \
      ! "video/x-raw, format=(string)GRAY16_LE" \
      ! filesink location=video.raw

  Display 640x480:
    gst-launch-1.0 -v v4l2src device="/dev/video0" \
      ! "video/x-raw, format=(string)GRAY16_LE, width=640, height=480" \
      ! videoconvert ! ximagesink sync=false

  Display 1280x1024:
    gst-launch-1.0 -v v4l2src device="/dev/video0" \
      ! "video/x-raw, format=(string)GRAY16_LE, width=1280, height=1024" \
      ! videoconvert ! ximagesink sync=false


ARGB888 (32-bit AR24/BGRA or AB24/RGBA, depending on L4T version)

  Same underlying RGB888 bytes either way — reported as BGRA on L4T 32.x
  and all 35.x (including 35.4.1-35.6.4), and as RGBA on L4T 36.x and
  later (see the note under the v4l2-ctl section above for why). Use
  eg_dt_camera_config_get.sh to check which one your board reports, then
  use the matching examples below — GStreamer fails with "can't handle
  caps"/"not-negotiated" if you pick the wrong one for your L4T version.

  Capture native ARGB888 to file (1 frame) — L4T 32.x/35.x (BGRA):
    gst-launch-1.0 -v v4l2src device=/dev/video0 num-buffers=1 \
      ! "video/x-raw, format=(string)BGRA" \
      ! filesink location=video.raw

  Capture native ARGB888 to file (1 frame) — L4T 36.x+ (RGBA):
    gst-launch-1.0 -v v4l2src device=/dev/video0 num-buffers=1 \
      ! "video/x-raw, format=(string)RGBA" \
      ! filesink location=video.raw

  Convert to RGB888 and save — L4T 32.x/35.x (BGRA):
    gst-launch-1.0 -v v4l2src device=/dev/video0 num-buffers=1 \
      ! "video/x-raw, format=(string)BGRA" \
      ! videoconvert ! video/x-raw,format=BGR \
      ! filesink location=video.raw

  Convert to RGB888 and save — L4T 36.x+ (RGBA):
    gst-launch-1.0 -v v4l2src device=/dev/video0 num-buffers=1 \
      ! "video/x-raw, format=(string)RGBA" \
      ! videoconvert ! video/x-raw,format=RGB \
      ! filesink location=video.raw

  Display 640x480 — L4T 32.x/35.x (BGRA):
    gst-launch-1.0 -v v4l2src device="/dev/video0" \
      ! "video/x-raw, format=(string)BGRA, width=640, height=480" \
      ! videoconvert ! ximagesink sync=false

  Display 640x480 — L4T 36.x+ (RGBA):
    gst-launch-1.0 -v v4l2src device="/dev/video0" \
      ! "video/x-raw, format=(string)RGBA, width=640, height=480" \
      ! videoconvert ! ximagesink sync=false

  Display 1280x1024 — L4T 32.x/35.x (BGRA):
    gst-launch-1.0 -v v4l2src device="/dev/video0" \
      ! "video/x-raw, format=(string)BGRA, width=1280, height=1024" \
      ! videoconvert ! ximagesink sync=false

  Display 1280x1024 — L4T 36.x+ (RGBA):
    gst-launch-1.0 -v v4l2src device="/dev/video0" \
      ! "video/x-raw, format=(string)RGBA, width=1280, height=1024" \
      ! videoconvert ! ximagesink sync=false

  Stream to UDP (GStreamer receiver, host 192.168.1.1):
    gst-launch-1.0 v4l2src device=/dev/video0 \
      ! "video/x-raw, format=(string)RGB, width=640, height=480" \
      ! videoconvert ! x264enc tune=zerolatency ! rtph264pay \
      ! udpsink host=192.168.1.1 port=50000

    Receiver:
      gst-launch-1.0 udpsrc port=50000 \
        caps="application/x-rtp, media=video, encoding-name=H264" \
        ! rtph264depay ! avdec_h264 ! autovideosink sync=false

  Stream to UDP (VLC receiver, host 192.168.1.1):
    gst-launch-1.0 v4l2src device=/dev/video0 \
      ! "video/x-raw, format=(string)RGB, width=640, height=480" \
      ! videoconvert ! x264enc key-int-max=12 ! mpegtsmux \
      ! udpsink host=192.168.1.1 port=50000

  Stream to TCP (VLC receiver):
    gst-launch-1.0 v4l2src device=/dev/video0 \
      ! "video/x-raw, format=(string)RGB, width=640, height=480" \
      ! videoconvert ! x264enc key-int-max=12 ! mpegtsmux \
      ! tcpserversink host=0.0.0.0 port=50000

================================================================================
OTHER CAMERAS (e.g. IMX219)
================================================================================

  v4l2-ctl -d /dev/video0 --set-fmt-video=width=1920,height=1080,pixelformat=RG10 \
    --stream-mmap

  export DISPLAY=:1
  gst-launch-1.0 nvarguscamerasrc sensor-id=0 \
    ! "video/x-raw(memory:NVMM), width=(int)1920, height=(int)1080, \
       format=(string)NV12, framerate=(fraction)30/1" \
    ! nvvidconv ! xvimagesink sync=false


================================================================================
NOTES
================================================================================

• Y16 (16-bit greyscale) is not supported on Jetson Nano (T210). Use AR24
  or YUYV instead.

• The AR24/AB24 split above is driven by GStreamer, not V4L2: NVIDIA's
  own vi5_formats.h/camera_common.c natively switched to RGBA32-only
  starting L4T 35.4.1 (v4l2-ctl always works fine there), but EG keeps
  ABGR32/AR24 available too through L4T 35.6.4 because gst-plugins-good
  1.16.3 (JetPack 5.x, Ubuntu 20.04) doesn't support the RGBA32 V4L2
  fourcc. L4T 36.x+ (JetPack 6.x+, GStreamer 1.20+) doesn't need that
  workaround and reports AB24 only, matching NVIDIA's table. L4T 32.x
  (T210/T186, VI2/VI4 pipeline) always reports AR24 — NVIDIA never
  changed that table on those older SoCs.

• For GStreamer, the format and dimensions are negotiated automatically
  when not explicitly constrained in the caps filter.

• Line continuations (\) are for readability. Copy commands as-is or
  remove backslashes and put everything on one line.

• DISPLAY=:1 sets the X11 display for graphical output on a remote host.

• On L4T 39.x (Ubuntu 24.04), replace ximagesink with autovideosink in the
  examples above: ximagesink fails there due to an XInput2 device-ID bug.
  autovideosink selects waylandsink or glimagesink automatically.
